## Data reset (needs your approval, runs on Railway)

The data is on the Railway volume. The reset runs inside the service when it starts, following the variable `ACC_RESET_DATA`:

| Value | What happens |
|---|---|
| `dry-run` | The deploy logs list what would be deleted (rows per table, files per folder, bucket objects). Nothing changes. |
| `EXECUTE-2026-11-25` | 1) full database backup to `/data/backups/acc-before-reset-<time>.db` · 2) footage jobs cancelled · 3) rows deleted, legacy tables and columns dropped (one transaction) · 4) volume folders deleted/emptied (`clips raw voice music work renders thumbs` removed; `files tmp incoming store` emptied) · 5) bucket objects under `footage/` deleted (if a bucket is set) · 6) checks: no rows left, no broken links (`foreign_key_check`), `integrity_check` ok. Runs **once** (marker file). |

Kept: users, sessions, `/data/backups`, every Railway variable (API keys, ElevenLabs, admin, bucket).
